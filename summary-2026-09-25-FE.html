Current Architecture & Fallback Orderโครงสร้างปัจจุบัน & ลำดับ Fallback

  • There's no centralized SEO component yet — SEO is split across each routing/page, e.g. app.tsx, home SEO.tsx, and various utility functions. app.tsx acts as the main fallback when a page doesn't define its own SEO. ตอนนี้ยังไม่มี SEO component กลาง แต่ SEO ถูกแยกอยู่ตามแต่ละ routing/page เช่น app.tsx, home SEO.tsx และ utility functions ต่าง ๆ โดย app.tsx ทำหน้าที่เป็น fallback หลัก หากหน้าไหนไม่ได้กำหนด SEO เอง
  • This lets each page have its own SEO without needing to redefine everything from scratch. ทำให้แต่ละหน้าสามารถมี SEO เฉพาะของตัวเองได้ โดยไม่จำเป็นต้องกำหนดทุกอย่างใหม่
API / Bridge Dataข้อมูลจาก API / Bridge → FE ConfigurationFE Configuration → Default in app.tsxDefault ใน app.tsx
Fallback order the system tries, top to bottomลำดับที่ระบบจะพยายามใช้ ไล่จากบนลงล่าง

Dynamic Metadata & Bridge ManagementDynamic Metadata & การจัดการผ่าน Bridge

  • Meta title, description, Open Graph, and Twitter tags can be pulled dynamically from the API — especially for Home, PLP, PDP, CMS, and Collection pages. Meta title, description, Open Graph และ Twitter tags สามารถดึงข้อมูลแบบ dynamic จาก API ได้ โดยเฉพาะหน้า Home, PLP, PDP, CMS และ Collection
  • Business users can manage Meta Title, Description, Keywords, and Breadcrumbs through Bridge — this data comes through the API and overrides the Frontend's default values. Business user สามารถจัดการข้อมูล เช่น Meta Title, Description, Keywords และ Breadcrumbs ผ่าน Bridge ได้ และข้อมูลเหล่านี้จะถูกส่งผ่าน API มา override ค่า default ของ Frontend

Multi-Country, Multi-Languageรองรับหลายประเทศ หลายภาษา

  • SEO can be split by country and language — e.g. Thailand can have a separate set of metadata for English and for Thai. SEO สามารถแยกตามประเทศและภาษาได้ เช่น Thailand สามารถมี metadata ภาษาอังกฤษและภาษาไทยคนละชุดกัน

Product SEO — Widgets, Headings & TypographySEO ระดับสินค้า — Widget, Heading & Typography

  • Product Detail uses a Widget system that can be reordered from Bridge, and can set the element tag (e.g. H1, H2, H4) to suit SEO needs, without having to change the core design system. Product Detail ใช้ระบบ Widget ที่สามารถ reorder ได้จาก Bridge และสามารถกำหนด element tag เช่น H1, H2, H4 เพื่อให้เหมาะกับ SEO โดยไม่จำเป็นต้องแก้ design system หลัก
  • The Design System already has typography variants with default font size, line height, weight, and heading tag — but FE can override the element tag via configuration/props when SEO needs a different semantic heading than the default. Design System มี typography variant ที่กำหนด default font size, line height, weight และ heading tag ไว้แล้ว แต่ Frontend สามารถ override element tag จาก configuration/props ได้ หาก SEO ต้องการ semantic heading ที่แตกต่างจาก default
  • Product title can be managed from Bridge, both per-product and via bulk CSV update, and that data can be used in the heading/H1. Product title สามารถจัดการได้จาก Bridge ทั้งแบบรายสินค้าและ bulk update ผ่าน CSV และสามารถนำข้อมูลเหล่านี้มาใช้ใน heading/H1 ได้

Open Graph & CMS OverridesOpen Graph & การ Override บน CMS

  • Open Graph image fallback generally picks from: 1) API, 2) Frontend configuration, 3) Default fallback — PDP can pull the image from the product's Gallery. เข้าใจ fallback ของ OG image แล้วว่าโดยทั่วไปจะเลือกจาก: 1) API 2) Frontend configuration 3) Default fallback ส่วน PDP สามารถดึงรูปจาก Gallery ของสินค้าได้
  • For campaigns or CMS pages that need specific metadata, meta tags can be set directly in the HTML/head to override the defaults — e.g. OG title, description, and image. สำหรับ campaign หรือ CMS page ที่ต้องการ metadata เฉพาะ สามารถกำหนด meta tags ใน HTML/head โดยตรง เพื่อ override ค่า default เช่น OG title, description และ image

Protecting Non-Production Environmentsป้องกัน SEO บน Environment ที่ไม่ใช่ Production

  • There are safeguards to stop URLs from local, development, and pre-production from being indexed by Google, via fallback links and robots metadata. มีการป้องกันไม่ให้ URL จาก local, development และ pre-production ถูก Google index ผ่าน fallback links และ robots metadata

Known SEO GapsSEO Gap ที่ยังต้องแก้

  • GapGap No centralized SEO component yet. ยังไม่มี centralized SEO component
  • GapGap Some pages still don't have a proper semantic H1. บางหน้ายังไม่มี semantic H1 ที่เหมาะสม
  • GapGap Some parts of the code are still hardcoded. มีบางส่วนที่ hardcode อยู่
  • GapGap The codebase structure will need to be adjusted based on the results of the SEO audit. ต้องมีการปรับโครงสร้าง codebase ตามผลจาก SEO audit
