WARRANTY Post-order + UI Kit

Post-order Kickoffเริ่มงานใน Post-order

  • Started Warranty work in the Post-order repo — branched off post-order following the approach LK's team recommended. เริ่มงานด้วยการทำ Warranty ใน Post-order repo โดยแตก branch จาก post-order ตามแนวทางที่ทีม LK แนะนำ
  • Started building Mock data based on the Figma design, using @lk/ui-kit as the main building block for the UI. เริ่มทำ Mock data โดยอ้างอิงจาก Design ใน Figma และใช้ @lk/ui-kit เป็นหลักในการสร้าง UI

UI Kit Architectureสถาปัตยกรรมของ UI Kit

  • Learning about the UI Kit made it clearer that a new component (e.g. Drawer / Sidebar) should be built in the UI Kit repo first, so it can be reused by Post-order and other repos. จากการเรียนรู้เรื่อง UI Kit ทำให้เข้าใจมากขึ้นว่า หากต้องสร้าง Component ใหม่ เช่น Drawer / Sidebar ควรสร้างใน UI Kit repo ก่อน เพื่อให้สามารถ reuse กับ Post-order และ repo อื่น ๆ ได้
  • Learned more about Theming, Design Tokens, Storybook, and Unit Tests — these let a component support multiple Brands and have clear, verified behavior before it's used in a Consumer Application. เข้าใจเพิ่มเติมเรื่อง Theming, Design Tokens, Storybook และ Unit Test ซึ่งช่วยให้ Component สามารถรองรับหลาย Brand และมี behavior ที่ชัดเจนก่อนนำไปใช้ใน Consumer Application

UI Kit Contribution Workflowขั้นตอนพัฒนา Component ใน UI Kit

  • For a new UI Kit component, branch off the active release branch, then: develop → test → open MR → merge → publish the package, before using it in another repo. สำหรับ Component ใหม่ใน UI Kit ควรแตก branch จาก active release branch แล้วพัฒนา → test → เปิด MR → merge → publish package ก่อนนำไปใช้งานใน repo อื่น

PAYMENT Google Pay Redirect Fix & Follow-on Bugs

Redirect Fix — Shipped to Preprodฟิกซ์เรื่อง Redirect — ขึ้น Preprod แล้ว

  • Doneเสร็จแล้ว Informed Tester and the FE team that the case of tapping the close button on the Google Pay popup and redirecting to /checkout/retry has been fixed. แจ้ง Tester และ FE team ว่าแก้ไขกรณีกดปุ่มปิด Google Pay popup แล้ว redirect ไป /checkout/retry เสร็จแล้ว
  • Doneเสร็จแล้ว The Lenskart FE side deployed it to Preprod successfully. ทาง FE ฝั่ง Lenskart นำขึ้น Preprod ให้เรียบร้อย

New Issue: "View Order Details" Buttonปัญหาใหม่: ปุ่ม "View Order Details"

  • Foundพบปัญหา After that, found that on the Retry page, the "View order details" button couldn't be tapped. หลังจากนั้นพบว่าในหน้า Retry ปุ่ม View order details ไม่สามารถกดได้
  • Initial investigation showed the code in the Checkout repo has no issue — tapping the button correctly navigates to /customer/account, following the existing flow. ตรวจสอบเบื้องต้นแล้วพบว่า code ใน Checkout repo ไม่มีปัญหา เพราะเมื่อกดปุ่ม ระบบสามารถ navigate ไป /customer/account ได้ตาม existing flow
  • The problem is at /customer/account, the My Account page of the OWNDAYS main website — a separate app/repo from Checkout. ปัญหาอยู่ที่ /customer/account ซึ่งเป็น My Account page ของ OWNDAYS main website และอยู่คนละ app/repo กับ Checkout
  • Root cause hypothesisข้อสันนิษฐาน The /customer/account page hit a gateway timeout while loading on Preprod — likely related to the My Account page's API/backend responding slowly or not at all in the environment under test. หน้า /customer/account เกิด gateway timeout ระหว่างโหลดบน Preprod จึงมีแนวโน้มว่าเกี่ยวข้องกับ API/backend ของหน้า My Account ที่ตอบสนองช้าหรือไม่ตอบสนองใน environment ที่กำลังทดสอบ

New Bug: Mobile New Tab Won't Closeบั๊กใหม่: New Tab บน Mobile ปิดไม่ได้

  • Foundพบปัญหา Then found another bug on Mobile: when Google Pay opens in a New Tab, the New Tab can't be closed — needs further checking of the popup/tab flow and behavior. หลังจากนั้นพบอีก bug บน Mobile กรณีเปิด Google Pay ใน New Tab แล้วไม่สามารถกดปิด New Tab ได้ จึงต้องตรวจสอบ flow และ behavior ของ popup/tab เพิ่มเติม
TAKEAWAYS Overall, from Todayสิ่งที่ได้จากวันนี้โดยรวม

Overall Takeawaysสรุปสิ่งที่ได้เรียนรู้

  • Got hands-on with real Warranty work in Post-order, and started understanding the UI development flow using the UI Kit more deeply. ได้ลงมือทำ Warranty จริงใน Post-order และเริ่มเข้าใจ flow การพัฒนา UI โดยใช้ UI Kit มากขึ้น
  • Understood that the UI Kit should be the main source of shared components, with Post-order consuming those components. เข้าใจว่า UI Kit ควรเป็น source หลักของ shared components และ Post-order ทำหน้าที่นำ component เหล่านั้นมาใช้งาน
  • Practiced isolating a Payment bug to figure out whether it's in the Checkout repo or an external application/backend — which makes it much clearer to scope the issue and hand it off to the right team. ได้ฝึกแยกปัญหาใน Payment ว่า bug อยู่ที่ Checkout repo หรือ external application/backend ซึ่งช่วยให้สามารถระบุ scope และส่งต่อปัญหาให้ทีมที่เกี่ยวข้องได้ชัดเจนขึ้น
  • In one day, touched UI implementation, shared component architecture, testing, and debugging across multiple applications/environments. ได้เรียนรู้ทั้งด้าน UI implementation, shared component architecture, testing และ debugging ระหว่างหลาย application/environment ในงานเดียวกัน
