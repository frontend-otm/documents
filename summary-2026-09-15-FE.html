things learned/shipped todayเรื่องที่เรียนรู้/ทำสำเร็จวันนี้ From local environment setup to a real, working Google Pay implementation ตั้งแต่ตั้งค่า local environment จนถึง Google Pay ที่ implement จริงและทำงานได้

Got the local dev environment fully workingแก้ปัญหารัน local environment จนสำเร็จ

  • Learned that Checkout's basePath forces every URL to be prefixed with /sg/en/checkout. เข้าใจว่า basePath ของ Checkout บังคับให้ทุก URL ต้องมี /sg/en/checkout นำหน้าเสมอ
  • Session/cart isn't tied to whichever repo's dev server is running — it's tied to the browser cookie — so switching between running Base (to shop) and Checkout (to pay) works without running both at once. รู้ว่า session/cart ไม่ผูกกับ repo ที่รันอยู่ แต่ผูกกับ cookie ในเบราว์เซอร์ — เลยสลับรัน Base (ซื้อของ) แล้วมารัน Checkout (จ่ายเงิน) ได้โดยไม่ต้องรันพร้อมกัน
  • Used a preprod account until the real payment-methods page rendered — saw GRABPAY, which directly confirmed the "generic component" theory. ใช้ account preprod จนเห็นหน้า payment methods จริง (เห็น GRABPAY ที่ยืนยันทฤษฎีเรื่อง generic component ได้ตรงๆ)

Understood the underlying mechanics more deeplyเข้าใจกลไกเบื้องหลังลึกขึ้น

  • apiWrapper (core-utils) is the central point every API call passes through — always returns the same response shape. apiWrapper (core-utils) คือจุดกลางที่ทุก API call ต้องผ่าน — คืนผลลัพธ์รูปแบบเดียวกันเสมอ
  • PaymentContainerRoot.tsx is the "decision brain" with no UI of its own; two gateways run side by side (Juspay/Primer). PaymentContainerRoot.tsx ทำหน้าที่ "สมองตัดสินใจ" ไม่มี UI ในตัวเอง มี 2 gateway ทำงานคู่กัน (Juspay/Primer)

Got Primer's official documentation from the team (LK)ได้เอกสารทางการของ Primer จากทีม (LK) มาอ้างอิง

  • Doc: primer.io/docs/connections/payment-methods/google-pay/overview เอกสาร: primer.io/docs/connections/payment-methods/google-pay/overview
  • Confirmed Google Pay genuinely needs frontend implementation work, not just waiting for backend — Primer classifies it as a "native payment method" (must render its own button), unlike Atome/GrabPay. ยืนยันว่า Google Pay ต้อง implement เพิ่มจากฝั่ง frontend จริง ไม่ใช่แค่รอ backend ทำเสร็จแล้วจบ — เพราะ Primer จัดกลุ่ม Google Pay เป็น "native payment method" (ต้องสร้างปุ่มเอง) คนละแบบกับ Atome/GrabPay

Actually implemented Google Pay in the Checkout repoลงมือ implement Google Pay จริงใน repo Checkout

  • Created PrimerGooglePay.tsx + updated the enum in types/payment.ts + added the dispatch case in PaymentScreen.tsx. สร้าง PrimerGooglePay.tsx + แก้ enum ใน types/payment.ts + เพิ่มจุด dispatch ใน PaymentScreen.tsx
  • Real bugBug จริง Ran type-check/lint/build until they actually passed — hit 2 real issues: the installed @lk/core-utils was older than expected (missing isBlocked), and EventTypes is a real TypeScript enum that had to be referenced correctly. รัน type-check/lint/build จนผ่านจริง เจอ bug จริงระหว่างทาง 2 จุด: @lk/core-utils เวอร์ชันที่ติดตั้งเก่ากว่าที่คาด (ไม่มี field isBlocked) และ EventTypes เป็น TypeScript enum ต้องเขียนให้ถูกรูปแบบ

Found a missing orderPayment call — caught by the team (Sandeep)เจอ bug ขาด orderPayment API call — ทีม (Sandeep) ตรวจเจอจากฝั่งหลังบ้าน

  • Real bugBug จริง Clicking Google Pay wasn't calling orderPayment at all. Traced the existing Primer Card flow and made Google Pay call processOrderPayment the same way (reusing the existing function, not duplicating it) — a good example of why this kind of integration bug needs real verification from both sides. ปุ่ม Google Pay กดแล้วไม่เรียก orderPayment เลย ต้องไล่เทียบกับ flow ของ Primer Card ที่มีอยู่แล้ว แล้วแก้ให้ Google Pay เรียก processOrderPayment แบบเดียวกัน (reuse function เดิม ไม่เขียนซ้ำ) — เป็นตัวอย่างที่ดีว่า bug ด้าน integration แบบนี้ต้องอาศัยการตรวจสอบจริงจากทั้งสองฝั่ง

Learned a UI trick to match the mockupเรียนรู้ trick ทำ UI ให้ตรงกับ mockup

  • Learnedเรียนรู้ Primer's native Google Pay button can't be triggered by code — reused the same pattern Apple Pay already uses: show a decorative radio row, and place the real, transparent button directly on top of it, so the click lands on the real button while the user sees the decorative one. ปุ่ม native ของ Primer (Google Pay) ไม่มีทาง trigger ด้วยโค้ดได้เอง ต้องใช้ pattern เดียวกับ Apple Pay ที่มีอยู่แล้ว — โชว์ radio row ปลอมไว้ แล้ววางปุ่มจริงแบบโปร่งใสทับไว้ด้านบน ให้คลิกโดนของจริงแต่มองเห็นของปลอม
Decorative row underneath, Primer's real Google Pay button transparently stacked on top — same trick already used for Apple Pay. แถวปลอมอยู่ข้างล่าง ส่วนปุ่ม Google Pay จริงของ Primer ถูกวางแบบโปร่งใสทับด้านบน — trick เดียวกับที่ใช้กับ Apple Pay อยู่แล้ว

Learned about logo copyright/complianceเรียนรู้เรื่อง compliance/ลิขสิทธิ์ของโลโก้

  • Resolvedแก้แล้ว Initially tried drawing the Google Pay logo by hand, then realized it's Google's trademark and shouldn't be copied that way — fixed it to pull logoImageUrl from the backend instead, same as every other payment method (Grab, Atome). No hardcoded asset left in the FE code. ตอนแรกลองวาดโลโก้ Google Pay เอง แต่รู้ตัวว่าเป็นเครื่องหมายการค้าของ Google ไม่ควรลอกแบบเอง — แก้ให้ดึง logoImageUrl จาก backend แทนเหมือน payment method อื่นทุกตัว (Grab, Atome) ไม่ hardcode asset ไว้ในโค้ด FE เลย
