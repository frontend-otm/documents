Owndays PDP Product Tags

Current state, feasibility, architectural constraints, and required changes for product badges on Owndays product detail pages.

English · Updated August 2026

Overview

PDP product badges are exposed through a single sortingTag field in the product API response (ProductResult). A separate persuasion field supports low-stock messaging but is not part of the primary badge system.

LayerLocation
Tag logicjuno-product/.../JunoUtils.java → getSortingTag()
PDP wiringjuno-product/.../ProductServiceImpl.java → constructFieldsInProductResult()
API schemajuno-schema/.../ProductResponse.json → sortingTag
Client-org config keysjuno-product/.../ClientOrgConfigKeyEnum.java

Key architectural constraints

1. Only one tag at a time

The API returns one sortingTag object, not an array. The first matching condition wins.

  1. Top PID
  2. Pre-order (isPreOrder = true)
  3. New arrivals (category or launch-date threshold)
  4. Best seller (category or sales-count threshold)
  5. Kids (category)
  6. Outlet (category + discount label)
  7. Clip-on (category)
Multiple badges require structural work. Showing combinations such as NEW + LOW STOCK needs an API/schema change and frontend updates, not backend configuration alone.

2. Owndays overrides generic tag logic

For Owndays products, the generic getSortingTag() path runs first. The result is then reset to null, and the Owndays-specific block (around line 2244 in JunoUtils.java) applies.

3. Two badge styles

StyleTags
Image badge (imageUrl set, empty label)NEW, Best Seller, Kids, Outlet, Clip-on
Text badge (label + colors)Pre-order, Top PID

sortingTagPreOrderImageUrl exists in configuration but is not wired into the Owndays pre-order block.

Tag-by-tag detail

NEW — Mostly working

How it works: A product receives the NEW image badge when it belongs to newLaunchCategoryId, or—if threshold logic is enabled—when launchedDate falls within thresholdForNewArrival days.

Config: thresholdBasedSortingTagEnabled, thresholdForNewArrival, newLaunchCategoryId, newLaunchImageUrl.

Data: launchedDate is indexed from ProductCountryAttributes. It is not sent by Owndays Product Sync V2 and is automatically set when a product is first activated.

Gap: “NEW” represents days since catalog activation, which may differ from the marketing launch date.

If activation date is unsuitable: add a launch-date field and mapping to Sync V2, or set it through existing country bulk/manual catalog flows; then configure threshold and image URL.

BEST SELLER — Mostly working

A product receives the image badge by membership in bestSellerCategoryId, or when lastThirtyDaysSalesCount > thresholdForSellingCount.

Config: thresholdBasedSortingTagEnabled, thresholdForSellingCount, bestSellerCategoryId, bestSellerImageUrl.

Data: BestSellerProductServiceImpl aggregates orders from SellingProductEntity, writes the 30-day count to Mongo, and re-indexes it to ES.

If missing: enable/configure thresholds, verify the aggregation job for the target countries, or assign products to the best-seller category.

LOW STOCK — Partial

Low-stock messaging exists, but not in the Owndays sortingTag chain. PDP uses persuasion when inventory is below thresholdInventoryMap. Color variants can also receive persuasion text under pdpColorVariantPersuasionThreshold. A Lenskart-only low-stock sortingTag path is not used by the Owndays block.

To make it a PDP badge: add a LOW STOCK branch and priority, add image/threshold configuration, decide whether persuasion remains, align frontend/backend behavior, and upload the badge asset. Effort: Medium.

PRE-ORDER NOW — Mostly working

The text badge appears when isPreOrder = true. Its label and text/background/gradient colors come from configuration. The flag is set through the country bulk CSV column Is Pre Order and indexed to ES; it is not included in Sync V2.

Config: sortingTagPreOrderLabel, sortingTagPreOrderTextColor, sortingTagPreOrderBgColor, sortingTagPreOrderStartColor, sortingTagPreOrderEndColor. The existing sortingTagPreOrderImageUrl needs wiring for an image-style badge.

PRE-ORDER EXCLUSIVE — Not implemented

No distinct attribute, flag, or tag logic exists. Implementation needs a new country-level product attribute, a bulk/sync/category data source, ES indexing, tag logic and priority, configuration, and frontend rendering. Product must also define how “exclusive” differs from ordinary pre-order. Effort: Medium.

ONLINE EXCLUSIVE — Not on PDP

Online Exclusive Sale (OES) exists for cart and order, not as a PDP sortingTag. Cart logic matches offerName or category ID, sets isOnlineExclusiveSale, and order persists it. OesHelper supports product filtering.

For PDP, reuse the same OES detection in the Owndays tag path, add badge configuration and priority, align rules with cart behavior, and ensure frontend rendering. Effort: Medium.

Verification

  1. Call the PDP API for a known Owndays product ID.
  2. Inspect sortingTag and, optionally, persuasion.
  3. For NEW/BEST SELLER, confirm imageUrl is populated when rules match.
  4. For PRE-ORDER, confirm label and colors when isPreOrder = true in ES/Mongo.
  5. Confirm that only one tag appears per product.

Recommended phases

Phase 1 — Configuration only

  • Enable threshold-based tags; set thresholds and image URLs.
  • Map new-arrival/best-seller categories if thresholds are not used.
  • Set isPreOrder by bulk for pre-order SKUs.

Delivers: NEW, BEST SELLER, PRE-ORDER NOW.

Phase 2 — Small backend changes

  • Add LOW STOCK to the Owndays priority chain.
  • Add ONLINE EXCLUSIVE to PDP using existing OES rules.
  • Optionally wire image-based PRE-ORDER and add launchedDate/isPreOrder to Sync V2.

Phase 3 — New attributes / structural change

  • Add PRE-ORDER EXCLUSIVE end to end.
  • If required, support multiple simultaneous tags through schema, API, and frontend changes.

Open product/design questions

  1. Should one badge or multiple badges be shown?
  2. What is the complete priority order, including LOW STOCK, ONLINE EXCLUSIVE, and PRE-ORDER EXCLUSIVE?
  3. Should every Owndays badge use an image, or can some remain text badges?
  4. How is PRE-ORDER EXCLUSIVE defined relative to PRE-ORDER NOW: flag, category, or offer?

ข้อจำกัดสำคัญของสถาปัตยกรรม

1. แสดงได้ครั้งละหนึ่งแท็ก

API ส่งคืน sortingTag หนึ่งออบเจ็กต์ ไม่ใช่อาร์เรย์ เงื่อนไขแรกที่ตรงจะถูกเลือก

  1. Top PID
  2. Pre-order (isPreOrder = true)
  3. สินค้าใหม่ (หมวดหมู่หรือเกณฑ์วันที่เปิดตัว)
  4. สินค้าขายดี (หมวดหมู่หรือเกณฑ์ยอดขาย)
  5. เด็ก (หมวดหมู่)
  6. Outlet (หมวดหมู่ + ป้ายส่วนลด)
  7. Clip-on (หมวดหมู่)
หลายป้ายต้องปรับโครงสร้างระบบ เช่น การแสดง NEW + LOW STOCK พร้อมกัน ต้องเปลี่ยน API/schema และ frontend ไม่สามารถทำได้ด้วยการตั้งค่า backend เพียงอย่างเดียว

2. ตรรกะ Owndays แทนที่ตรรกะทั่วไป

ระบบเรียก getSortingTag() แบบทั่วไปก่อน จากนั้นรีเซ็ตผลเป็น null แล้วใช้บล็อกเฉพาะ Owndays (ประมาณบรรทัด 2244 ใน JunoUtils.java)

3. รูปแบบป้ายสองแบบ

รายละเอียดแต่ละแท็ก

NEW — ใช้งานได้เกือบครบ

สินค้าได้รับป้ายรูปภาพ NEW เมื่ออยู่ใน newLaunchCategoryId หรือเมื่อเปิดใช้ตรรกะแบบ threshold และ launchedDate อยู่ภายในจำนวนวันที่กำหนดโดย thresholdForNewArrival

การตั้งค่า: thresholdBasedSortingTagEnabled, thresholdForNewArrival, newLaunchCategoryId, newLaunchImageUrl

ข้อมูล: launchedDate ถูกทำดัชนีจาก ProductCountryAttributes แต่ไม่ได้ส่งผ่าน Owndays Product Sync V2 และถูกกำหนดอัตโนมัติเมื่อเปิดใช้งานสินค้าเป็นครั้งแรก

ช่องว่าง: “NEW” จึงหมายถึงจำนวนวันหลังเปิดสินค้าใน catalog ซึ่งอาจไม่ตรงกับวันเปิดตัวทางการตลาด

หากใช้วัน activation ไม่ได้ ให้เพิ่มฟิลด์วันที่เปิดตัวและ mapping ใน Sync V2 หรือใช้ country bulk/manual catalog ที่มีอยู่ แล้วกำหนด threshold และ URL รูปภาพ

BEST SELLER — ใช้งานได้เกือบครบ

สินค้าได้รับป้ายรูปภาพเมื่ออยู่ใน bestSellerCategoryId หรือเมื่อ lastThirtyDaysSalesCount > thresholdForSellingCount

การตั้งค่า: thresholdBasedSortingTagEnabled, thresholdForSellingCount, bestSellerCategoryId, bestSellerImageUrl

ข้อมูล: BestSellerProductServiceImpl รวมคำสั่งซื้อจาก SellingProductEntity เขียนยอดขาย 30 วันลง Mongo และทำดัชนีใหม่ไปยัง ES

หากยังไม่แสดง ให้เปิดใช้/กำหนด threshold ตรวจสอบ aggregation job ของประเทศเป้าหมาย หรือเพิ่มสินค้าเข้าหมวดสินค้าขายดี

LOW STOCK — มีบางส่วน

มีข้อความสินค้าใกล้หมดอยู่แล้ว แต่ไม่ได้อยู่ในลำดับ sortingTag ของ Owndays บน PDP ระบบใช้ persuasion เมื่อสต็อกต่ำกว่า thresholdInventoryMap และตัวเลือกสียังแสดงข้อความตาม pdpColorVariantPersuasionThreshold ได้ เส้นทาง low-stock แบบ sortingTag ของ Lenskart ไม่ถูกใช้ในบล็อก Owndays

หากต้องการเป็นป้าย PDP: เพิ่มเงื่อนไขและลำดับความสำคัญ LOW STOCK, เพิ่มค่ารูปภาพ/threshold, ตัดสินใจว่าจะคง persuasion หรือไม่, จัดพฤติกรรม frontend/backend ให้ตรงกัน และอัปโหลด asset ป้าย ความยาก: กลาง

PRE-ORDER NOW — ใช้งานได้เกือบครบ

ป้ายข้อความจะแสดงเมื่อ isPreOrder = true โดย label และสีข้อความ/พื้นหลัง/ไล่สีมาจาก configuration ค่านี้กำหนดผ่านคอลัมน์ Is Pre Order ใน country bulk CSV และทำดัชนีไปยัง ES แต่ยังไม่มีใน Sync V2

การตั้งค่า: sortingTagPreOrderLabel, sortingTagPreOrderTextColor, sortingTagPreOrderBgColor, sortingTagPreOrderStartColor, sortingTagPreOrderEndColor ส่วน sortingTagPreOrderImageUrl ที่มีอยู่ต้องเชื่อมเพิ่มหากต้องการป้ายแบบรูปภาพ

PRE-ORDER EXCLUSIVE — ยังไม่ได้พัฒนา

ยังไม่มี attribute, flag หรือตรรกะแท็กที่แยกจาก pre-order ปกติ ต้องเพิ่ม product attribute ระดับประเทศ แหล่งข้อมูล bulk/sync/category การทำดัชนี ES ตรรกะและลำดับแท็ก configuration และการแสดงผล frontend รวมถึงกำหนดนิยาม “exclusive” ให้แตกต่างจาก pre-order ปกติ ความยาก: กลาง

ONLINE EXCLUSIVE — ยังไม่มีบน PDP

Online Exclusive Sale (OES) มีใน cart และ order แล้ว แต่ยังไม่เป็น sortingTag บน PDP ระบบ cart ตรวจจาก offerName หรือ category ID แล้วตั้ง isOnlineExclusiveSale; ระบบ order บันทึกค่านี้ และ OesHelper ใช้กรองสินค้า

สำหรับ PDP ให้ใช้ตรรกะตรวจ OES เดิมในเส้นทางแท็ก Owndays เพิ่ม configuration และ priority ของป้าย ใช้กฎเดียวกับ cart และรองรับการแสดงผลใน frontend ความยาก: กลาง

ขั้นตอนตรวจสอบ

  1. เรียก PDP API ด้วย Owndays product ID ที่ทราบแน่ชัด
  2. ตรวจ sortingTag และ persuasion หากต้องการ
  3. สำหรับ NEW/BEST SELLER ตรวจว่า imageUrl มีค่าเมื่อเงื่อนไขตรง
  4. สำหรับ PRE-ORDER ตรวจ label และสีเมื่อ isPreOrder = true ใน ES/Mongo
  5. ยืนยันว่าแต่ละสินค้าแสดงเพียงหนึ่งแท็ก

ระยะการพัฒนาที่แนะนำ

ระยะ 1 — ตั้งค่าเท่านั้น

  • เปิดใช้ threshold-based tags และกำหนด threshold/URL รูปภาพ
  • ทำ category mapping สำหรับสินค้าใหม่/ขายดีหากไม่ใช้ threshold
  • กำหนด isPreOrder ผ่าน bulk สำหรับ SKU ที่เปิดจอง

ได้แท็ก: NEW, BEST SELLER, PRE-ORDER NOW

ระยะ 2 — ปรับ backend ขนาดเล็ก

  • เพิ่ม LOW STOCK ในลำดับ Owndays
  • เพิ่ม ONLINE EXCLUSIVE บน PDP โดยใช้กฎ OES เดิม
  • อาจเพิ่มป้าย PRE-ORDER แบบรูปภาพ และเพิ่ม launchedDate/isPreOrder ใน Sync V2

ระยะ 3 — ฟิลด์ใหม่ / เปลี่ยนโครงสร้าง

  • เพิ่ม PRE-ORDER EXCLUSIVE แบบ end-to-end
  • หากจำเป็น รองรับหลายแท็กพร้อมกันด้วยการเปลี่ยน schema, API และ frontend
