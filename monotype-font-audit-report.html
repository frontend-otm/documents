⚠ Risk Assessment Summary

Overall compliance exposure by font category.

HIGH RISK — Self-Hosted Fonts (10 font sets, 40+ font files) Font files stored in public/fonts/ and served directly from the web server or CDN. This constitutes web font embedding / self-hosting, which requires a commercial license from Monotype. Without a valid license, this may result in copyright infringement claims and significant financial liability.
MEDIUM RISK — PDF & Typekit Fonts dompdf fonts: Used for server-side PDF generation. Requires font embedding rights, typically covered by the original font license or a separate server license.
Neuzeit Grotesk (Typekit): Covered by Adobe Fonts subscription, but the subscription must be active and usage must comply with Adobe’s terms of service.
LOW RISK — System Font References Fonts like Gill Sans Nova referenced in CSS font-family stacks rely on the end user’s operating system. No font files are distributed, so no additional licensing is typically required.

✅ Recommendations

Suggested actions to achieve full licensing compliance.

  1. 1
    Verify existing Monotype licenses. Check whether OWNDAYS holds any active Monotype, Linotype, or ITC font licenses (e.g., Monotype Fonts subscription, fonts.com license, or direct purchase agreements) that cover web embedding and self-hosting for all identified fonts.
  2. 2
    Audit Adobe Fonts subscription. Confirm the Adobe Fonts (Typekit) subscription is active and covers all Typekit kit IDs used in the project. Verify that Neuzeit Grotesk and other Typekit fonts are within the subscription’s page view limits.
  3. 3
    Acquire proper licenses or replace fonts. For any self-hosted fonts without a valid license, either:
    • Purchase appropriate Monotype web font licenses, or
    • Replace with open-source alternatives (e.g., Inter, Noto Sans, Source Sans for body text; Libre Franklin, Work Sans for headlines).
  4. 4
    Remove unused font files. Identify font files in public/fonts/ that are no longer referenced anywhere in the codebase and remove them to reduce the compliance surface area.
  5. 5
    Review dompdf configuration. Ensure the PDF generation pipeline uses fonts with proper embedding rights. Consider switching to open-source alternatives like Noto Sans CJK for Asian language support.
  6. 6
    Establish a font governance policy. Create a documented process for introducing new fonts to the project, requiring license verification before any font is added to the codebase.
