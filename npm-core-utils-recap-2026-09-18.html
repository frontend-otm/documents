FE NPM Core Utils Package: Setup, Versioning & Publishing

What Core Utils IsCore Utils คืออะไร

  • Learned the structure and purpose of Core Utils — an npm package shared between Base and Checkout, used to handle and format data coming from the API. เรียนรู้โครงสร้างและการใช้งานของ Core Utils ว่าเป็น npm package ที่ใช้ร่วมกันระหว่าง Base และ Checkout เพื่อจัดการและ format ข้อมูลจาก API
  • Understood the difference between Lenskart Core Utils and OWNDAYS Core Utils, and how each package's version is managed separately. เข้าใจความแตกต่างระหว่าง Lenskart Core Utils และ OWNDAYS Core Utils รวมถึงการจัดการ version ของแต่ละ package

Versioning Rulesกฎเรื่อง Versioning

  • Understood the principle of checking the version on the npm registry before publishing, and bumping the version number correctly to avoid a duplicate-version conflict. เข้าใจหลักการตรวจสอบ version บน npm registry ก่อน publish และการเพิ่ม version ให้ถูกต้อง เพื่อป้องกัน version ซ้ำ
  • Learned how to install a new Core Utils version in Base, and that a version not yet published to the registry simply cannot be installed. เรียนรู้วิธีติดตั้ง Core Utils version ใหม่ใน Base และเข้าใจว่า version ที่ยังไม่ได้ publish บน registry จะไม่สามารถติดตั้งได้
  • Good to knowข้อสังเกต Learned that the package can be built and published from a release branch — it is not restricted to any one specific branch. เรียนรู้ว่า package สามารถสร้างและ publish จาก release branch ได้ ไม่จำเป็นต้องจำกัดอยู่ที่ branch ใด branch หนึ่ง

Publish Workflowขั้นตอนการ Publish

  • Learned the steps to create and publish a private npm package — from logging in, syncing the code, building the package, to publishing it. เรียนรู้ขั้นตอนการสร้างและ Publish private npm package ตั้งแต่การ login, sync code, build package และ publish
  • Important habitสิ่งที่ต้องทำเสมอ Understood why it matters to commit and push the code right after publishing a package — so the Git repository and the npm package version stay in sync, preventing version-tracking problems down the line. เข้าใจความสำคัญของการ commit และ push code หลังจาก publish package เพื่อให้ Git repository และ npm package version ตรงกัน และป้องกันปัญหาในการติดตาม version ในอนาคต
Login → Sync Code → Check Registry Versionเช็ค Version บน Registry → Bump Versionเพิ่ม Version → Build → Publish → Commit & Push → Install in BaseInstall ใน Base
Why FE's session matteredสรุปคุณค่าของฝั่ง FE Now have a full picture of the Core Utils package lifecycle — what it is, how versioning works, and the exact publish workflow — plus the discipline habit (commit & push right after publish) that keeps Git and npm from drifting out of sync. ตอนนี้มีภาพรวมของ Core Utils package แบบครบวงจร — มันคืออะไร versioning ทำงานยังไง และขั้นตอน publish ที่ถูกต้อง พร้อมนิสัยที่ต้องทำเสมอ (commit & push ทันทีหลัง publish) เพื่อไม่ให้ Git กับ npm version หลุดไม่ตรงกัน
BE ARES Build & Membership Rank in the Pricing Engine

ARES / Membership Rank DependenciesDependency ของ ARES / Membership Rank

  • 1. Archiva & Build — Understood how to resolve an ARES build issue caused by a library version that has not been deployed to Archiva yet. เข้าใจการแก้ปัญหา Build ARES จาก Library Version ที่ยังไม่ได้ Deploy บน Archiva
  • 2. Version Management — Learned to separate a Test Version from the Release Version, to prevent the real version from being deployed before it is tested. เรียนรู้การแยก Test Version และ Release Version เพื่อป้องกันการ Deploy Version จริงก่อนทดสอบ
  • 3. Schema Integration — Understood how to use the correct juno-schema version, and the Cart code changes needed to support memberRank. เข้าใจการใช้ juno-schema Version ที่ถูกต้อง และการแก้ไขโค้ด Cart เพื่อรองรับ memberRank
  • 4. Membership Rank Flow — Understood how memberRank is passed from Cart to ARES, so Pricing Rules work correctly. เข้าใจการส่งค่า memberRank จาก Cart ไปยัง ARES เพื่อให้ Pricing Rules ทำงานได้ถูกต้อง
  • 5. Microservices & Deployment — Learned about deploying services independently, handling null values, and creating a merge branch to prepare the Cart deployment. เรียนรู้การ Deploy Service แยกกัน การรองรับค่า null และการสร้าง Merge Branch เพื่อเตรียม Deploy Cart
Why BE's session matteredสรุปคุณค่าของฝั่ง BE We now understand the dependency between Schema, Cart, and ARES more clearly, along with the Build, Versioning, and Deployment process needed to support Membership Rank in the Pricing Engine. พวกเราเข้าใจ Dependency ระหว่าง Schema, Cart และ ARES รวมถึงกระบวนการ Build, Versioning และ Deployment เพื่อรองรับ Membership Rank ใน Pricing Engine ได้ชัดเจนยิ่งขึ้น
